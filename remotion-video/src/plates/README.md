# Light-texture plates

Four abstract background plates, each a procedural recreation of one
supplied stock reference. Nothing is filmed or sampled: every frame is
generated by a custom WebGL fragment shader running through PixiJS v8
inside Remotion.

| Composition | Length | Reference | Look |
|---|---|---|---|
| `GoldenRays` | 420f / 14.000s | `bd91a4b1` (14.014s @ 23.976) | Sun through foliage — blown gold core, crepuscular shafts, olive greens |
| `SilverBokeh` | 570f / 19.000s | `f6f0d1b3` (18.986s @ 29.97) | High-key silver bokeh on a near-white field |
| `DeepBlueDust` | 390f / 13.000s | `5d412a9b` (13.013s @ 29.97) | Deep navy, ringed blue bokeh, twinkling dust |
| `BokehCurtain` | 300f / 10.000s | `97b80acb` (10.000s @ 30.0) | Defocused string-light curtain, amber and steel blue |

Each is registered twice — `<Name>` at 1920×1080 and `<Name>4K` at
3840×2160 — from one component, one schema and one set of props.

## Rendering

```bash
npx remotion render GoldenRays   out/GoldenRays_1080p.mp4 --codec=h264 --crf=16 --pixel-format=yuv420p --image-format=png
npx remotion render GoldenRays4K out/GoldenRays_2160p.mp4 --codec=h264 --crf=16 --pixel-format=yuv420p --image-format=png
```

`--image-format=png` matters here. These plates are almost entirely smooth
gradient, which is exactly what JPEG intermediates band and block on; the
default JPEG quality leaves visible artefacts in the bokeh falloff.

On a machine with no GPU, `remotion.config.ts` points Chrome at ANGLE's
SwiftShader backend so a real GL2 context is available. With a GPU present,
dropping `Config.setChromiumOpenGlRenderer("swangle")` will render far
faster — a 4K pass is impractical on software GL but routine on hardware.

## How the plates are built

### Everything is a pure function of loop position

Remotion renders frames out of order and across several browser tabs at
once, so nothing may depend on wall-clock time or on state carried from a
previous frame. Each shader receives `uT`, the loop position in `[0,1)`,
and computes the frame from scratch. That is what makes the output
deterministic and the render parallelisable.

### The loops are seamless by construction, not by cross-fade

Motion is assembled only from terms that return to their frame-0 value at
`uT = 1`:

- oscillation — `cos(TAU * (k*uT + phase))` with **integer** `k`
- noise flow — `loopFbm()`, which cross-fades two time-offset samples of
  the same field so it appears to drift while returning to its start
- grain — quantised to whole frames off `uT`, so the loop point does not
  show up as a single-frame noise pop

Measuring the references settled the approach: all four have **zero** net
translation, so the motion is sway and twinkle in place rather than
scrolling. That removes the need for wrap-around drift, which cannot loop
cleanly against a position-hashed field without visible tiling.

Verified on the delivered renders by comparing the wrap step against a
normal one-frame step — see `docs/plates-verification.md`.

### Density comes from a jittered grid, not a sprite list

A pixel inspects only the 3×3 grid cells around it, and disc radius is
held below the cell pitch, so no light outside that neighbourhood can
reach it. Cost per pixel is therefore fixed no matter how many discs the
layer notionally contains — which is what makes a field of thousands of
highlights renderable on software GL.

### One image at two resolutions

Every length inside a shader is measured in 1080p-referred pixels and
multiplied by `uScale`, derived from the output width. The 4K composition
is therefore the *same image* at twice the sample rate, not a
differently-composed one — confirmed at a mean difference of 0.09/255
between a 4K still downsampled to 1080p and the native 1080p still.

### Bokeh is modelled, not blurred

`bokehProfile()` builds a defocused highlight the way a lens makes one: a
near-flat disc bounded by the aperture, a brighter rim where the lens edge
concentrates energy, and a soft falloff whose width stands in for distance
from the focal plane. `DeepBlueDust` additionally hollows the interior,
which is what turns a blob into the ring bokeh that characterises its
reference.

## Retuning

Every plate exposes its palette and behaviour as Zod-typed props, so they
can be scrubbed live in `npx remotion studio` and overridden per render
with `--props`. `seed` reshuffles every hashed field — disc placement,
sizes, twinkle phases — without touching the motion design, which is the
quickest way to get a different take on the same look.
